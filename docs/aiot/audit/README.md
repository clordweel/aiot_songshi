# 执行留痕（Audit）

任何**真实执行**若对环境产生写影响或运维后果，结束后在此目录追加一条**简报**（不必详细），便于人工审批与事后核查。

## 建议记一笔的场景

- 在 VM 上执行 `bench` / shell 导致配置或数据变更
- ERPNext / Frappe **API 写操作**（创建/更新/提交 DocType 等）
- PVE 快照、磁盘、网络等变更
- 部署、迁移、回滚

**可不记**：纯规划、本地只读查文档、对话讨论未触达环境。

## 简报最低字段

每条可新文件 `YYYY-MM-DD_short-slug.md` 或在单文件按日期追加小节：

- **时间**（UTC 或团队约定本地时区）
- **执行主体**（可选：姓名、工单号、会话说明）
- **目标环境**（VM/站点标识，**不要**写密码）
- **动作类型**：`bench` / `pve` / `api_write` / `deploy` / 其他
- **摘要**：1～3 条要点或命令级提要（非完整终端转储）
- **结果**：`ok` / `failed` + 必要时一行原因
- **审批**（可选）：工单链接或「已批准」说明

## 敏感信息

禁止在 audit 正文中出现 API Secret、私钥、数据库口令；可写「凭据来自 env / 密钥管理器」。

## 是否进 Git

默认 **摘要级可提交**，便于 PR 与评审对齐上下文。若合规禁止入库，则改用外部工单系统，但须保证**仍有一处可追溯**与本 README 说明一致。

## 简报模板（复制即用）
