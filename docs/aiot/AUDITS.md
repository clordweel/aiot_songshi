# 执行留痕（Audit）

任何**真实执行**若对环境产生写影响或运维后果，结束后在**仓库根目录下的 `audits/`** 追加一条**简报** Markdown（不必详细），便于人工审批与事后核查。

**说明**：`audits/` 与本仓库 `docs/` **同级**，且默认由 `.gitignore` **排除版本跟踪**；若合规允许摘要入库，可团队另行约定（例如工单系统）。下文字段与模板仍适用。

## 建议记一笔的场景

- 在 VM 上执行 `bench` / shell 导致配置或数据变更
- ERPNext / Frappe **API 写操作**（创建/更新/提交 DocType 等）
- PVE 快照、磁盘、网络等变更
- 部署、迁移、回滚

**可不记**：纯规划、本地只读查文档、对话讨论未触达环境。

## 简报最低字段

每条可新文件 `YYYY-MM-DD_short-slug.md`；**同日多条**或需稳定排序时，建议文件名带序：**`YYYY-MM-DD_HHmmss_short-slug.md`**（**到秒即可**，不用毫秒）。若批量改名，可用**文件创建时间**（或团队约定的落盘时刻）生成 `HHmmss`；同一秒撞名时顺延 1 秒。**文件名前缀表示落盘/编辑时刻时，可能与正文「业务日期」不一致，以正文 `- 时间：` 为准。**也可在单文件按日期追加小节。

- **时间**：**必须含时分秒**，格式 **`YYYY-MM-DD HH:mm:ss`**，并注明时区（示例：**`2026-05-08 14:30:00 CST (UTC+8)`** 或 ISO **`2026-05-08T14:30:00+08:00`**）。纯日期无法区分同日多次执行，也会造成按字符串排序时顺序错误。
- **执行主体**（可选：姓名、工单号、会话说明）
- **目标环境**（VM/站点标识，**不要**写密码）
- **动作类型**：`bench` / `pve` / `api_write` / `deploy` / 其他
- **摘要**：1～3 条要点或命令级提要（非完整终端转储）
- **结果**：`ok` / `failed` + 必要时一行原因
- **审批**（可选）：工单链接或「已批准」说明；若记审批时刻，使用 **`审批时间：YYYY-MM-DD HH:mm:ss`（同上时区规则）**，便于与执行时间分开排序、核对。

## 敏感信息

禁止在 audit 正文中出现 API Secret、私钥、数据库口令；可写「凭据来自 env / 密钥管理器」。

## 是否进 Git

本仓库默认 **`audits/` 不入库**（见根目录 `.gitignore`）。若合规禁止入库至任意 Git，须改用外部工单系统，但须保证**仍有一处可追溯**与本说明一致。

## 简报模板（复制即用）

```markdown
## YYYY-MM-DD HH:mm:ss — 简短标题

- 时间：YYYY-MM-DD HH:mm:ss CST (UTC+8)（或 ISO8601 + 时区）
- 环境：
- 类型：
- 摘要：
- 结果：
- 审批（可选）：
- 审批时间（可选）：
```

**历史条目说明**：若早期简报仅有日期、后补时分秒，须在 `时间` 旁加「补录」或在摘要首行说明；**新执行请始终写真实时刻**。
