# 变更前快照与回滚思路

在 **重大变更**（大版本升级、`migrate` 规模大、危险二开、数据库结构变更、不可逆数据导入）或 **高风险操作**（生产切流量、内核/存储调整）前，**先具备可恢复点**，再继续执行。

## 1. 首选：虚拟化 / 云平台快照

若在 **PVE** 或其它 hypervisor 上运行：

- 为整台 VM 或磁盘创建**快照**，命名建议含日期与工单/变更摘要。
- 具体命令（`qm snapshot`、`pct` 等）依平台与权限，由运维执行并记录 ID。

## 2. 备选：Ubuntu LVM 快照（若可用）

当根卷或数据卷位于 **LVM** 且团队策略允许 **LVM snapshot** 时：

- 先确认 VG 有**足够空闲 extent** 容纳 COW（写时复制）增长，避免快照自动失效。
- 创建前阅读发行版文档：`lvcreate -s` / `lvremove` 等流程因 LVM 版本略有差异。
- **注意**：LVM 快照**不能替代**异地备份；长时挂载大块写入负载可撑满快照空间。

快速**只读**探查是否使用 LVM（示例，需在目标机执行）：

```bash
lsblk
sudo pvs 2>/dev/null; sudo vgs 2>/dev/null; sudo lvs 2>/dev/null
```

是否采用 LVM 快照由你与存储策略决定；不可用或未启用 LVM 时回到 **§1** 或文件级备份。

## 3. 与 audit 配合

快照创建完成后：在 `docs/aiot/audit/` 按 [README.md](../audit/README.md) 记一笔（类型可写 `pve` / `backup` / `lvm_snapshot` 等），便于审批与事后核对。

## 4. 对代理的期望

在提议或执行上述高风险步骤前，**主动提醒**操作者完成 §1 或 §2 中适用的一项，再继续具体命令或 `bench` 操作。
